# EchoVoice 远程控制实施计划

更新时间：2026-07-25

状态：控制面申请、批准、过期、租约心跳、限流、设备绑定、键鼠转发、原生注入、3 秒本地优先和撤销闭环已达到生产测试条件；WebRTC DataChannel、真实 Windows 双机注入、弱网和长期稳定性尚待验收，整体仍是实验功能。后续开发以本文件为准。

## 0. 2026-07-24 实施进度

本轮已完成：

- 明确 Web 只能作为控制端，Web 发起共享时远程控制固定为关闭，并以 EchoVoice Tooltip 说明边界。
- `RemoteControlSession` 已绑定共享者和控制者的 `participant_id`。
- 申请、列表、批准、拒绝、撤销、尊重窗口和输入鉴权均校验具体设备参与者。
- 控制状态和输入事件只投递到目标设备，不再广播到同一成员的全部关联设备。
- 停止观看、离开频道、切换频道和设备断线按具体观看设备清理；同一成员的其他观看设备不被误删。
- Go 集成测试覆盖同一成员第二台设备无法批准、撤销或发送输入，并验证第二台设备可以建立独立观看和申请。
- 浏览器自动化测试覆盖 Web 开关始终关闭、不可点击、无原生 Tooltip 且边界说明可见。

截至当日，阶段 1 尚待完成：申请过期、授权代次、租约/心跳、申请限流、待处理数量上限、管理员强制结束，以及权限变化后的主动撤销；这些控制面缺口已在 2026-07-25 的生产化加固中补齐。

## 0.1 2026-07-25 基础闭环进度

本轮新增：

- 共享者批准前先启动 Windows 原生输入宿主，避免控制端收到 `active` 时宿主仍未就绪。
- 原生宿主的启动、停止和输入执行使用同一串行操作锁，避免重复批准或快速事件创建多个 Hook。
- 共享端按 WebSocket 顺序串行调用 Tauri 输入命令，避免后发指针事件先执行后让点击或按键被判定为旧序列。
- 新增 `release_all` 输入事件。退出控制、焦点丢失、指针取消和按 Esc 时会释放全部远程按键和鼠标按钮。
- 窗口共享绑定开始捕获时的进程 ID；每次输入重新读取 HWND 边界，并在指针注入前检查目标点没有被其他窗口覆盖。
- 增加多显示器负坐标映射测试。
- 共享端在任意页面都能看到远控申请或“正在被控制”状态条，并可直接拒绝、批准或紧急结束控制。
- 页面刷新或工作区重连不会继承旧控制权，已加载的待处理/活动授权会主动撤销。
- 浏览器端自动化已使用真实 EV Server 验证：观看、申请、批准、鼠标移动、点击、滚轮、键盘、释放全部输入、撤销、审计以及刷新后撤销。

当前输入仍通过事件 WebSocket 转发。这满足生产测试，但尚未完成计划中的 WebRTC DataChannel 和公网弱网生产验收。

## 0.2 2026-07-25 生产测试加固

本轮新增：

- 待批准申请 60 秒过期，活动控制采用 10 秒租约；控制端每 3 秒心跳续租，停止观看、离开语音、权限失效或设备不匹配时拒绝续租并撤销。
- 每个参与设备限制为每分钟 10 次申请，每个共享最多 5 个待处理申请，并向 UI 返回可区分的限流错误。
- 会话增加 `grant_generation`、`expires_at_ms`、`lease_until_ms` 和 `transport_state` 元数据，为后续 DataChannel 授权代次握手保留稳定边界。
- 具备成员管理权限的管理员可以强制撤销活动控制；过期和租约失效均写入审计并发送目标设备事件。
- Go 单元与 HTTP 集成测试覆盖过期、心跳设备绑定、待处理上限和申请洪泛；真实 EV Server 浏览器自动化覆盖控制闭环和边界拒绝。
- 共享观看者列表改为挂载到应用顶层的视口安全浮层，避免被服务器/频道栏遮挡，并新增窄窗口遮挡回归断言。

阶段 1 的控制面安全基线已经完成。授权代次的输入传输握手、DataChannel 关闭处理、真实双机注入和两小时弱网验收仍属于后续生产发布门槛。

## 1. 目标

第一阶段交付以下完整闭环：

1. Windows 桌面客户端共享屏幕或窗口时，可选择“允许其他用户申请控制”。
2. Windows 桌面客户端和 Web 客户端都可以作为控制端。
3. 共享者必须逐次明确批准；同一共享同时只允许一个控制者。
4. 共享显示器时控制范围限制在该显示器；共享窗口时控制范围限制在目标窗口。
5. 被控端发生真实鼠标或键盘输入后，立即释放远程按键并进入 3 秒尊重窗口。
6. 结束共享、停止观看、离开频道、断线、权限变化或主动撤销时立即失效。
7. 服务端保留授权和会话审计，但不记录按键、鼠标坐标或输入内容。

## 2. 第一阶段不包含

- Web 客户端作为操作系统级被控端。浏览器沙箱不允许网页向本机系统注入输入。
- 远程剪贴板、文件拖放、管理员免确认接管、无人值守控制。
- UAC 安全桌面、登录界面、锁屏界面和高于 EchoVoice 完整性级别的应用。
- 通过提权绕过 Windows UIPI。EchoVoice 不应为了远程控制默认以管理员身份运行。
- macOS、Linux 被控端的正式支持；这些平台在 Windows 版本稳定后分阶段接入。

### 2.1 Web 能力边界

1. Web 客户端可以观看并申请控制由受支持桌面客户端发起的共享。
2. Web 客户端发起屏幕共享时，“允许其他用户申请控制”固定为关闭，客户端必须向 EV Server 发送 `remote_control_allowed=false`。
3. EV Server 不得为 Web 共享创建远程控制授权；不能仅依赖前端禁用状态作为安全边界。
4. 浏览器提供的 Captured Surface Control 等能力只可操作被捕获浏览器标签页的滚动或缩放，不等同于 EchoVoice 的操作系统级远程控制，也不作为降级方案。
5. 将来浏览器能力发生变化时，必须重新完成权限、安全、平台兼容和端到端验收，不能自动放开该开关。

## 3. 当前代码审计

已经存在：

- `remote_control_enabled` 服务开关。
- `request_remote_control`、`accept_remote_control` 权限。
- 共享前“允许其他用户申请控制”开关。
- 申请、批准、拒绝、撤销和尊重窗口 API。
- 服务端单控制者、序列号、速率限制、权限复核和审计骨架。
- 前端申请、批准、结束控制和画面输入捕获 UI。
- Windows `SendInput` 输入注入、低级鼠标/键盘 Hook 和 3 秒本地输入检测。
- 服务端和 Rust 单元测试的基础覆盖。

仍然缺失或不够可靠：

1. 控制授权只绑定 `member_id`，没有绑定具体设备和语音参与者。关联多个设备后，同一成员的其他设备理论上可以参与批准或发送输入。
2. 屏幕共享观看者目前主要按成员记录，不能严格确认是哪一个设备正在观看。
3. “批准”后直接进入 active，没有等待原生输入宿主和控制传输都准备完成。
4. 输入走全局事件 WebSocket，没有独立背压、延迟、丢弃策略和传输诊断。
5. Windows 窗口模式只依赖坐标边界和前台窗口，仍需处理遮挡、窗口移动、DPI、子窗口和目标进程校验。
6. 当前没有真实 Windows 被控端 + Web/Desktop 控制端的自动化端到端测试。
7. 没有租约和心跳，异常断线后的会话回收主要依赖外围状态变化。
8. 缺少始终可见的被控提示、紧急停止入口和系统权限预检。
9. 现有项目计划把远程控制标记为完成，与实际成熟度不符。

## 4. 最终架构

### 4.1 控制平面

EV Server 始终是授权权威，负责：

- 校验服务器开关、角色权限、频道权限和语音参与状态。
- 创建申请、批准、拒绝、撤销、暂停和过期状态。
- 将会话绑定到 `share_id`、共享者 participant、控制者 participant 和设备 session。
- 签发短期、不可复用的控制授权代次 `grant_generation`。
- 处理租约、心跳、权限变化和断线清理。
- 写入不包含输入内容的审计日志。

### 4.2 输入数据平面

生产目标使用屏幕共享现有 PeerConnection 上的 WebRTC DataChannel：

- `ev-control-motion-v1`：无序、最多重传 0 次，只发送最新指针移动和连续滚轮输入。
- `ev-control-reliable-v1`：有序可靠，发送按键、鼠标按下/抬起、暂停、释放全部输入和撤销确认。
- 如果媒体连接经 TURN 中继，控制数据同样由自建 TURN 转发，不依赖第三方服务。
- 当前服务端 WebSocket 输入转发保留为开发诊断路径，DataChannel 验收后不作为默认生产路径。

服务端不会查看 DataChannel 中的每一个输入事件，因此被控端必须再次校验控制 ID、授权代次、参与者、序列号、租约、尊重窗口和目标源。服务端仍可随时撤销授权并关闭通道。

### 4.3 状态机

```text
pending
  -> rejected
  -> approved_waiting_host
       -> active
       -> failed
active
  -> suspended_local
       -> active
  -> revoking
       -> revoked
  -> expired
```

规则：

- 申请默认 60 秒过期。
- 批准后 15 秒内原生宿主或 DataChannel 未就绪则失败。
- active 每 3 秒续租，连续 10 秒没有心跳则过期。
- 所有状态变更必须幂等；重复批准、撤销和断线清理不能产生第二个会话。
- suspended 期间输入直接丢弃，不在恢复后补放。

## 5. 安全模型

### 5.1 设备级绑定

`RemoteControlSession` 增加：

- `owner_participant_id`
- `controller_participant_id`
- `owner_device_session_id`（仅服务端内部保存）
- `controller_device_session_id`（仅服务端内部保存）
- `grant_generation`
- `expires_at_ms`
- `lease_until_ms`
- `transport_state`

所有批准、输入和撤销都必须匹配创建申请时的具体设备。事件只能发送到目标 participant，不能广播到同一成员的全部设备。

### 5.2 本地双重校验

Windows 原生宿主每次执行输入前检查：

1. 当前控制 ID 和授权代次仍有效。
2. 当前屏幕共享 session 仍在运行且仍是原来的捕获源。
3. 本地尊重窗口已经结束。
4. 序列号递增且输入类型、坐标、按键和值域合法。
5. 窗口/显示器边界、DPI 和目标进程仍匹配。
6. 目标不是安全桌面，也没有被 UIPI 阻止。

### 5.3 窗口范围限制

- 坐标必须依据捕获帧对应的实际内容矩形映射，不能只使用开始共享时保存的窗口尺寸。
- 窗口移动、缩放、最大化、DPI 切换后更新目标几何代次。
- 每次点击前校验目标 HWND、根窗口和进程 ID；窗口被销毁或来源变化立即撤销。
- 指针位置落在目标窗口外、被其他进程窗口遮挡或当前焦点无法安全切换时拒绝该事件。
- 窗口模式拦截 Win、Alt+Tab、Ctrl+Esc、PrintScreen 等逃离目标范围的组合键。
- 全屏模式仍不支持 Ctrl+Alt+Delete、UAC 安全桌面和锁屏控制。

### 5.4 3 秒尊重窗口

- Windows Hook 必须先在原子状态中写入 `respect_until`，再做网络通知。
- 检测到本地输入时同步释放所有远程按下的键和鼠标按钮，避免粘键。
- 原生宿主是第一道拒绝层，控制端 UI 和服务端状态是第二、第三道拒绝层。
- 连续本地输入会延长窗口到“最后一次输入 + 3 秒”。
- 共享者可通过常驻控制条立即结束控制；后续增加本地紧急停止快捷键。

### 5.5 隐私与审计

可以记录：申请者、共享者、频道、设备参与者 ID、来源类型、开始/结束时间、时长、结束原因、传输类型和错误码。

禁止记录：按键内容、鼠标坐标、窗口标题、剪贴板内容和被控应用输入文本。

## 6. UI 流程

### 6.1 共享者

1. 屏幕共享配置中，远程控制开关默认关闭且每次共享单独确认。
2. 不支持宿主能力的平台禁用开关，并使用 EchoVoice Tooltip 解释原因；Web 端始终显示为关闭且不可操作。
3. 收到申请时显示置顶申请条和系统通知，包含申请者头像、名称、共享范围和允许/拒绝按钮。
4. 批准后显示常驻“正在被 XXX 控制”，并提供醒目的结束按钮。
5. 本地输入时显示 3 秒暂停倒计时，但不阻塞共享画面和语音。

### 6.2 控制者

1. 只有正在观看、拥有权限且共享允许申请时才显示“申请控制”。
2. 批准后仍需点击“开始控制”，避免一批准就捕获键盘。
3. 控制区域聚焦后捕获普通键鼠；Esc 只退出本地控制捕获，不会撤销授权。
4. 明确显示连接中、可控制、被控端本地优先、网络中断和已撤销状态。
5. Web 控制端提示浏览器快捷键和系统快捷键可能无法转发。

## 7. 平台范围

| 平台 | 作为控制端 | 作为被控端 | 首期范围 |
| --- | --- | --- | --- |
| Windows Tauri | 支持 | 支持 | 正式实现 |
| Web | 支持普通键鼠 | 不支持 | 正式实现控制端 |
| macOS Tauri | 后续支持 | 后续支持 | 先完成权限和能力探测 |
| Linux Tauri | 后续支持 | 后续支持 | 优先 XDG RemoteDesktop Portal |
| Android/iOS/HarmonyOS | 后续支持触控映射 | 不支持 | 移动端阶段处理 |

Windows 使用 `SendInput`，受 UIPI 和前台窗口策略限制；失败时必须向用户显示明确原因，不得静默提权或假装成功。

macOS 需要 Accessibility 授权，使用 CGEvent/Event Tap；权限未授予时只能观看，不能接受控制。

Linux Wayland 使用 XDG RemoteDesktop Portal，由桌面环境显示系统授权界面。不会采用要求 root 权限的通用 `/dev/uinput` 作为默认方案。

## 8. 开发阶段

### 阶段 0：纠正基线与实验开关

- 将远程控制标记为实验功能，不再在计划中标记为生产完成。
- 为当前 API、Rust 命令和 UI 流程补充状态图和错误码清单。
- 增加 `EV_REMOTE_CONTROL_EXPERIMENTAL` 或等价配置，正式部署默认关闭。

验收：未显式开启时，前端和 API 都不能发起远程控制。

### 阶段 1：设备级会话与服务端状态机（已完成）

- 改造观看者记录和 RemoteControlSession，绑定 owner/controller participant。
- 实现过期、租约、心跳、幂等和精确 participant 投递。
- 增加申请频率限制、最大待处理申请数和管理员强制结束权限。
- 补齐权限变化、设备切换、断线、离开频道和停止共享清理。

验收：同一成员的第二台设备无法批准、发送输入或继承另一设备的控制权。

### 阶段 2：可替换的原生输入宿主

- 将 `remote_control.rs` 拆为平台无关状态机、坐标转换和 Windows InputBackend。
- 为真实注入与测试记录器定义同一接口。
- 完成多显示器、负坐标、缩放、DPI、窗口移动和 pressed-state 清理。
- 补齐窗口前台、遮挡、进程、UIPI 和来源销毁检测。

验收：对专用测试窗口可以稳定移动、点击、滚动和输入，越界事件全部拒绝。

### 阶段 3：DataChannel 控制传输

- 在现有屏幕共享 PeerConnection 中加入 motion/reliable 两条 DataChannel。
- 实现授权代次握手、序列号、指针合并、队列上限、RTT 和断线诊断。
- motion 队列永远只保留最新位置；可靠队列不能丢失按下/抬起事件。
- DataChannel 关闭时立即释放全部远程按键并撤销会话。

验收：公网 TURN 和局域网直连都能控制，连续移动鼠标不会阻塞点击和键盘释放。

### 阶段 4：申请、批准和控制 UI

- 完成共享者申请通知、确认弹层、常驻控制状态条和紧急停止入口。
- 完成控制端开始/退出控制、暂停倒计时和错误反馈。
- 所有文本加入中英文 i18n，菜单、Tooltip、对话框使用 EchoVoice 自有组件。

验收：用户无需打开开发者控制台即可判断当前控制状态和失败原因。

### 阶段 5：生命周期与恢复

- 处理刷新、休眠、网络切换、WebSocket 重连、PeerConnection 重建和服务端重启。
- 控制权不跨页面刷新自动恢复；恢复观看后必须重新申请和批准。
- 所有异常路径执行 release-all，不能残留按键或鼠标按下状态。

验收：反复申请/撤销 100 次、断网和关闭客户端都不会留下活动控制会话或粘键。

### 阶段 6：自动化与生产验收

- Go：状态机、设备隔离、权限、限流、过期和 `go test -race`。
- Rust：坐标转换、快捷键过滤、pressed-state、尊重窗口和伪 InputBackend。
- 浏览器：两个客户端完成申请、批准、DataChannel、暂停和撤销流程。
- Windows 桌面：控制真实测试窗口，覆盖显示器和窗口两种来源。
- 网络：局域网、TURN、公网高延迟、丢包和重连。
- 安全：畸形输入、越界坐标、重放序列、旧授权代次和错误设备。
- 稳定性：至少 2 小时持续共享与间歇控制。

验收通过后，才移除“实验功能”标记。

## 9.1 基础双机测试步骤

前置条件：

1. 更新并重启 EV Server；客户端和服务器都需要包含本轮 `release_all` 协议改动。
2. 在服务器设置中开启“屏幕共享”和“远程控制”。
3. 共享者拥有“允许远程控制申请”权限，控制者拥有“申请远程控制”权限。
4. 被控端必须使用 Windows Tauri 桌面客户端；控制端可以使用 Windows 桌面客户端或 Web 客户端。
5. 建议先打开记事本作为安全测试目标。不要用管理员权限启动记事本，EchoVoice 也不需要以管理员身份运行。

操作流程：

1. 两个用户进入同一语音频道。
2. Windows 被控端选择记事本窗口，开启“允许其他用户申请控制”，然后开始共享。
3. 控制端点击“观看”，再点击“申请控制”。
4. 被控端顶部会出现全局申请条；确认申请者名称后点击“允许控制”。
5. 控制端打开共享大画面并点击“开始控制”。
6. 在画面内测试鼠标移动、单击、滚轮和普通文本输入；按 Esc 只退出本地控制捕获，不会结束授权。
7. 被控端主动移动鼠标或按任意键，控制端应立即看到 3 秒本地输入优先倒计时，期间远程输入不能生效。
8. 通过被控端顶部“结束控制”或控制端“结束控制”撤销；撤销后所有按下状态必须释放，继续输入不得影响被控端。
9. 再次批准控制后刷新控制端页面，旧授权应自动失效，必须重新观看、申请和批准。

已知系统边界：

- Web 只能作为控制端，不能作为操作系统级被控端。
- Windows UIPI 会阻止普通权限 EchoVoice 控制管理员权限应用，这是预期安全边界。
- 目标窗口被最小化、销毁、进程身份变化、无法切到前台或目标点被其他窗口覆盖时，输入会被拒绝。
- 本轮可以做基础功能测试，但不代表已通过公网弱网、TURN、两小时稳定性和安全审计。

## 10. 官方技术依据

- [Microsoft SendInput](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-sendinput)：说明输入注入和 UIPI 完整性级别限制。
- [Microsoft SetForegroundWindow](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setforegroundwindow)：说明前台窗口切换受系统策略限制。
- [Apple CGEvent](https://developer.apple.com/documentation/coregraphics/cgevent)：macOS 低级输入事件创建、发布和 Event Tap。
- [Apple AXIsProcessTrustedWithOptions](https://developer.apple.com/documentation/applicationservices/1459186-axisprocesstrustedwithoptions)：Accessibility 权限检查和系统提示。
- [XDG RemoteDesktop Portal](https://flatpak.github.io/xdg-desktop-portal/docs/doc-org.freedesktop.portal.RemoteDesktop.html)：Wayland 下受用户授权的键鼠控制和绝对坐标输入。
- [W3C WebRTC](https://www.w3.org/TR/webrtc/)：DataChannel 的有序、无序和有限重传模式。
